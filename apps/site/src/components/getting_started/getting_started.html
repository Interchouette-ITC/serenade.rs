DOCUMENTATION · FIRST STEPS

Get to know{{ space }}Serenade.

Install Serenade from crates.io, then run the core bundle demo and four runnable front-end modes: server-rendered HTML, a client-rendered SPA, static-site generation, and a Universal app with a live backend.

1. Install Serenade

Install Rust 1.100 or newer and the WebAssembly target, then the Serenade CLI and the{{ space }}serenade-framework{{ space }}crate from crates.io, imported as{{ space }}serenade. You do not need to install Trunk: the first SPA, SSG, or Universal build downloads Serenade's managed Trunk, a prebuilt and checksum-verified binary. 

{{ setupCommands }}

2. Run the examples from source

The examples live in the Serenade repository and need GNU Make. Clone it, run the workspace tests, then start the small bundle sample. The demo prints registered bundles, a greeting, event subscribers, and routes, then exits. 

{{ coreCommands }}

To try the interactive console instead, run{{ space }}make console ARGS='serenade:about', or add{{ space }}ARGS=--interactive{{ space }}to open the interactive picker.

3. Choose a web mode

Run these commands from the Serenade repository root. HTML and Universal run a local server; SPA and SSG create static build output.

SERVER · HTML

A server-rendered app

Run{{ space }} MyFeed, the fuller HTML example, on your machine. 

make html

Open http://127.0.0.1:8080/. The process stays running until you stop it.

BUILD · SPA

A client-rendered app

Build the Leptos SPA and its interactive counter with Serenade's managed Trunk. 

{{ spaCommands }}

Open http://127.0.0.1:4173/. The build output is examples/demo-monorepo/apps/demo-spa/dist/.

BUILD · SSG

Prerendered pages, hydrated

Build static HTML for the home and about routes, plus the browser hydration bundle. 

{{ ssgCommands }}

Open http://127.0.0.1:4173/ or http://127.0.0.1:4173/about/. Generated files are in examples/demo-monorepo/apps/demo-ssg/dist/.

SERVER · UNIVERSAL

A frontend with a live backend

Build the frontend, then run the backend that serves assets, JSON, and a server-rendered page. 

make universal

Open http://127.0.0.1:8080/ and http://127.0.0.1:8080/cms/hello. Stop the process when finished.

One local server at a time

HTML and Universal both use 127.0.0.1:8080 by default. Stop one before starting the other. The SPA and SSG examples share a port only when you serve their generated files; stop that preview server before reusing port 4173.

4. Keep exploring

Use{{ space }}make html-all,{{ space }}make spa-all,{{ space }}and{{ space }}make ssg-all{{ space }}to select every registered app in those modes. Each command currently has one demo app. Read the example guides for details and environment settings.

5. Choose your building blocks

Start with the components your product needs. Select an HTTP adapter and persistence strategy deliberately; Serenade does not require one server or ORM.

Serenade 1.0 on crates.io

All crates share one version. Maturity varies by crate: check each crate's README, tests, and API documentation before adopting it.

Coding agents

Source-backed help for Serenade and Rangular

The standalone documentation MCP searches guides and example source, gives app-building workflows, and parses Rangular templates. Each result identifies the embedded source version and revision.

Choose the{{ space }}serenade,{{ space }}rangular, or{{ space }}all{{ space }}profile. Template diagnostics use the released parser and are not an application build or AOT check.

Install the binary, then configure a stdio client: 

cargo install --locked serenade-rangular-mcp
{{ mcpConfig }}

Local stdio tools can scaffold projects and run Cargo, including build scripts and tests; use a client that requests approval. The existing Serenade CLI, managed Trunk and Cargo also run locally. The free hosted HTTP endpoint is read-only and can have a cold start.
