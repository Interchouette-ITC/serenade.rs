SERENADE · THE ARCHITECTURE

Symfony-inspired architecture. Rust-native implementation.

What if Symfony’s ideas were built for Rust?

Symfony showed how a framework can be a set of independent components, brought together by an application kernel and extended through bundles. Serenade takes inspiration from that architecture and gives it a Rust shape: explicit composition, Cargo-managed crates, and room to choose the infrastructure your application needs.

Serenade is an independent Rust project—not a PHP port, a Symfony compatibility layer, or an affiliated Symfony product.

THE COMPOSITION MODEL

Four parts. One application.

Each part has a job. Your application brings them together; it stays in charge of the result.

01 LIFECYCLE Kernel

Creates the application lifecycle: register bundles, compile, boot, and shut down.

↓
02 APPLICATION COMPOSITION Bundles

Group services, configuration, routes, subscribers, and commands into reusable units.

↓
03 CAPABILITIES Components

Offer focused building blocks—such as DI, events, HTTP, console, security, and forms—that can also be used independently.

↓
04 INFRASTRUCTURE BOUNDARIES Adapters

Connect framework contracts to choices such as Actix Web, Axum, and external services.

THE ARCHITECTURAL INSPIRATION

Small pieces, composed deliberately.

A kernel coordinates the application. Bundles contribute capabilities. Components have clear boundaries and can stand on their own. This is the Symfony-shaped influence—not a promise to reproduce every Symfony feature or API.

THE RUST-NATIVE CHOICES

Explicit dependencies, familiar tools.

Cargo remains the package manager. Rust traits and types define the contracts. Choose an HTTP adapter and persistence layer for your application; Serenade does not mandate an ORM or a single server.

A FRAMEWORK, NOT A PREBUILT PRODUCT

Start with the foundation.
Assemble what you need.

Serenade provides reusable infrastructure; your product owns its domain and its choices. Add framework components through bundles, or use a component directly when the kernel is more than you need.

01

Cargo owns dependencies

No second package manager. Add the crates your application uses with the tooling Rust already provides.

02

Bundles compose capabilities

Register related services, configuration, routes, and event subscribers as application units.

03

Infrastructure stays a choice

Use an adapter where it helps. Keep server, storage, and transport decisions at your application boundary.

Pre-1.0, with components at different stages.

Serenade is actively evolving. The architecture is a direction, not a claim that every component is equally complete or production-ready. Check each crate’s documentation, examples, and tests before adopting it.
